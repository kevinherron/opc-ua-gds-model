# Project Context

**Tech stack:** Java 17, Maven multi-module.

`opc-ua-gds-model` provides Eclipse Milo model classes for the OPC UA GDS information model
(namespace `http://opcfoundation.org/UA/GDS/`), generated from the GDS NodeSet2 file.

## Module Boundaries

- **gds-model-core**: NodeId constants, structured DataTypes, and the DataType and binary dictionary
  initializers.
- **gds-model-client**: Client-side ObjectType interfaces and their `*Node` implementations.
- **gds-model-server**: Server-side ObjectType interfaces and their `*Node` implementations.

## Generated Code

Everything under `src/main/java` is generated by
[opc-ua-codegen2](https://github.com/kevinherron/opc-ua-codegen2). Do not hand-edit it; regenerate
and copy the output in, mapping packages to modules:

| Generated package                     | Module           |
| ------------------------------------- | ---------------- |
| `com.digitalpetri.opcua.gds`          | gds-model-core   |
| `com.digitalpetri.opcua.gds.types`    | gds-model-core   |
| `com.digitalpetri.opcua.gds.client.*` | gds-model-client |
| `com.digitalpetri.opcua.gds.server.*` | gds-model-server |

The generator emits redundant `import java.lang.*` statements and does not wrap lines to the
formatter's width, so run `mvn -q spotless:apply` after copying generated code in.

## Building and Testing

Compile without running tests:

```bash
mvn -q clean compile
```

Compile, test, and run code quality checks:

```bash
mvn -q clean verify
```

## Code Formatting

This project uses Spotless with Google Java Format. The `spotless:check` goal is bound to the
`verify` phase and will fail the build if code is not properly formatted. To fix violations:

```bash
mvn -q spotless:apply
```

Google Java Format is pinned to 1.28.0, the last release that runs on JDK 17. Bumping it requires
moving the build to JDK 21+.

## Toolchain

`mise.toml` pins the JDK and Maven versions. Run `mise install` to set them up.
